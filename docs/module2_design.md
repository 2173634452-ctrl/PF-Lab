## 2.1 异常值检测与处理 — 为什么用"3个异常"作为删除阈值？

### 异常值的来源

在海水养殖物联网监测系统中，传感器可能因以下原因产生异常数据：

| 原因       | 典型表现             | 对数据的影响             |
| ---------- | -------------------- | ------------------------ |
| 设备老化   | 传感器灵敏度下降     | 数值持续偏离正常范围     |
| 供电故障   | 电压不稳导致读数跳变 | 偶发性极端值             |
| 人工增氧   | 增氧机开启           | 溶解氧短时间内剧烈升高   |
| 投饵/换网  | 人为干扰水体         | 多个参数同时出现异常波动 |
| 4G信号干扰 | 数据传输丢包/错码    | 单点数据损坏             |

### 异常值判定标准

本系统依据任务书规定的合理范围表进行判定：

| 参数                   | 最小值 | 最大值 | 单位 |
| ---------------------- | ------ | ------ | ---- |
| 水温 (Temp)            | -5     | 40     | ℃   |
| 盐度 (Salinity)        | 0      | 45     | PSU  |
| pH                     | 6.5    | 9.0    | —   |
| 溶解氧 (DO)            | 0      | 15     | mg/L |
| 降水量 (Precipitation) | 0      | 500    | m    |
| 气温 (Air_temp)        | -10    | 50     | ℃   |

### "3个异常"阈值的合理性分析

任务书要求：**异常参数 ≥ 3个 → 整条删除；异常参数 < 3个 → 修复**。

这个阈值设计是有实际依据的：

**为什么 ≥ 3 个异常就删除整条记录？**

1. **传感器级联故障特征**：当一条记录中多个参数同时异常（如水温+溶解氧+pH都偏离正常），通常是传感器节点整体故障或供电中断导致的大面积数据损坏。此时整条记录的6个参数都可能不可靠（即使某些参数表面上"在范围内"），因此直接删除更安全。
2. **数学依据**：一条记录有6个参数。如果3个（50%）已经明确异常，剩余3个的可信度也大打折扣——贝叶斯推断表明，在此情况下剩余参数为正常的后验概率显著低于独立随机概率。
3. **实际养殖经验**：在水产养殖中，水温、溶解氧、pH三者存在耦合关系（水温升高→溶解氧降低→pH随之变化）。如果这三者同时"异常"，说明要么是极端事件（如赤潮），要么就是传感器整体故障——而极端事件的发生概率远低于传感器故障。

**为什么 < 3 个异常就修复而非删除？**

1. **数据珍贵性**：每条记录代表5分钟的时间窗口，23,203条记录覆盖约80天的连续监测。丢弃过多数据会破坏时间序列的连续性，影响后续统计分析。
2. **单点故障可修复**：单一参数异常（如仅水温偏高）通常是该传感器的瞬时噪声，其余5个参数仍然可靠。此时用均值逼近法插值比整条删除更合理。
3. **统计学实践**：在时间序列分析中，孤立异常值通常采用插值/填充处理，而不是删除整条记录。

### 算法设计：两遍扫描法

```
第一遍（统计）：
  遍历所有有效记录
    统计每条记录的异常参数个数
    记录异常时间范围
    标记各参数是否异常 → 存入临时数组

第二遍（处理）：
  A. 修复阶段（先执行）：
     遍历记录，跳过标记为"待删除"的
       对每个异常参数调用均值逼近法填充
     
  B. 删除阶段（后执行）：
     写指针紧凑化：write_pos 跟踪保留位置
       跳过标记为"待删除"的记录
       其余记录前移
```

**为什么先修复后删除？** 因为均值逼近法需要向前/向后查找有效记录。如果先删除，会导致记录索引变化，影响填充值的准确性。

### 异常值处理方法对比（文献综述）

| 方法       | 原理                        | 优点         | 缺点             | 本系统采用               |
| ---------- | --------------------------- | ------------ | ---------------- | ------------------------ |
| 直接删除   | 移除整条异常记录            | 简单可靠     | 丢失有效信息     | 仅对≥3异常使用          |
| 均值填充   | 用全局均值替换              | 简单         | 忽略时间序列特性 | 兜底方案                 |
| 均值逼近法 | 用前后第n个有效值的均值填充 | 保留局部趋势 | 对连续异常敏感   | ✅ 主要方案              |
| 线性插值   | 用前后值线性拟合            | 平滑自然     | 对突变无能为力   | 未采用                   |
| KNN填充    | 用相似记录的均值            | 精度高       | 计算量大         | 未采用（超出本课程范围） |

**结论**：任务书要求的"≥3删除、<3均值逼近法填充"策略，是在**数据保留**与**数据质量**之间的合理平衡点，符合实际工程实践。

## 2.2 缺失值处理 — 均值逼近法详解

### 缺失值的三种形态

在CSV数据中，缺失值可能以多种形式出现：

| 类型     | 表示形式     | CSV中示例                          | 程序如何识别          |
| -------- | ------------ | ---------------------------------- | --------------------- |
| 空值     | 连续逗号     | `25.6,,8.15,6.80,0.001,27.8`     | `strlen(token)==0`  |
| 特殊数值 | -999 / -9999 | `25.6,-999,8.15,6.80,0.001,27.8` | 字符串比较 `"-999"` |
| NaN      | 文本标记     | `25.6,NaN,8.15,6.80,0.001,27.8`  | 字符串比较 `"NaN"`  |

模块一的数据加载阶段已将上述三种形态统一处理：无法解析的字段设为 `NaN`（Not a Number），并将整条记录标记为 `valid = false`。模块二在此基础上进行填充。

### 均值逼近法公式

任务书给出的公式：

\[
a_i = \frac{a_{i-n} + a_{i+m}}{2}
\]

其中：

- \(a_i\) = 第 \(i\) 个缺失数据（待填充值）
- \(a_{i-n}\) = 前面第 \(n\) 个**有效**数据（默认 \(n=10\)）
- \(a_{i+m}\) = 后面第 \(m\) 个**有效**数据（默认 \(m=10\)）

**公式含义**：不是简单地取前后所有值的平均，而是精准定位到"第10个有效值"——跳过了中间可能存在的其他缺失值，确保取到的锚点是真实的原始数据。

### 图解示例

假设时间序列如下（N=缺失，数字=有效值）：

```
位置:  ...  i-12  i-11  i-10  i-9  i-8  i-7  i-6  i-5  i-4  i-3  i-2  i-1   i
数值:  ...  8.1   8.0   7.9   N    7.8   7.7   N    7.6   7.5   7.4   7.3   N    ?
                                                                   ↑           ↑
                                                          第10个有效值=7.4   待填充
```

向后查找第10个有效值（跳过位置 i-10 的N和 i-6 的N）：找到 `a_{i-10} = 7.4`

同样方法向前查找第10个有效值：找到 `a_{i+10}`

最终填充值：\(a_i = (7.4 + a_{i+10}) / 2\)

### 边界处理策略

实际数据中经常会遇到边界情况，本系统按以下优先级处理：

```
优先级1：前后方向都有第10个有效值
  → a_i = (a_{i-n} + a_{i+m}) / 2

优先级2：仅一个方向有第10个有效值
  → a_i = 该方向的有效值（直接取用）

优先级3：两方向都不足10个有效值
  → a_i = 该参数的全数据集均值（兜底方案）
```

**为什么兜底用全局均值？** 当某个参数在一条记录的邻近范围内缺乏有效参考时，说明该区域数据质量普遍较差。此时使用全局均值虽然不够精确，但至少不会引入离谱的偏差值。

### 为什么 n=m=10？

- \(n=m=10\) 意味着参考点距离当前位置约 **50分钟**（采集间隔5分钟 × 10）
- 在海洋养殖环境中，水质参数的自然变化速度较慢——50分钟内的波动通常是噪声，真正的趋势变化需要数小时
- 10个点的距离足够排除局部噪声的干扰，同时不会因距离太远而失去时间相关性
- 如果设置过小（如n=m=2），填充值会过度受邻近噪声影响
- 如果设置过大（如n=m=50），参考点时间距离太远（4小时），可能已处于不同的环境状态

## 2.3 数据滤波 — 移动平均法设计分析

### 为什么要滤波？

传感器数据通过4G无线模块远程传输，容易受到以下干扰：

| 噪声来源     | 频率特征 | 对数据的影响          |
| ------------ | -------- | --------------------- |
| 近地电磁噪声 | 高频     | 数值出现短时尖峰/毛刺 |
| 收发器热噪声 | 随机高频 | 数值随机小幅度抖动    |
| 4G信号波动   | 间歇性   | 数据偶尔缺失后被填充  |

**滤波的目的**：滤除短期随机干扰，让长期变化趋势更加清晰，便于后续的趋势分析和预测建模。

### 移动平均法公式

\[
y[i] = \frac{x[i-k] + \cdots + x[i] + \cdots + x[i+k]}{N}
\]

其中：

- \(N = 2k + 1\) 为窗口大小（必须为奇数，确保中心对称）
- \(k = (N-1)/2\) 为半窗口大小
- \(x[i]\) 为原始数据，\(y[i]\) 为滤波后数据

**通俗理解**：把当前点和它前后各 k 个邻居的值加在一起求平均，用平均值代替当前值。就像给曲线"磨皮"——去掉毛刺，保留轮廓。

### 滤波参数选择

本系统对 **水温、溶解氧、pH、盐度** 四个核心参数进行滤波。降水量和气温不参与滤波——降水量大部分时间为0或极小值，气温变化缓慢、本身已是低频信号。

### 边界处理方案

当 \(i < k\)（数组开头）或 \(i > n-1-k\)（数组结尾）时，无法取到完整的 \(2k+1\) 个点。本系统采用**非对称窗口**：

\[
\text{实际窗口} = [\max(0, i-k),\ \min(n-1, i+k)]
\]

\[
\text{除数} = \text{实际窗口内的数据点数}
\]

**示例**（窗口=5，k=2）：

- \(i=0\)：窗口=[0, 2]，取3个值，除以3
- \(i=1\)：窗口=[0, 3]，取4个值，除以4
- \(i=2\) 及以上：窗口=[i-2, i+2]，取5个值，除以5

这种方法的优点是不会在边界处产生人为的"突变"。

### 窗口大小与噪声抑制程度的关系

本系统在控制台实时输出滤波前后标准差对比：

```
  水温(Temp)          滤波前标准差: 1.2345  →  滤波后标准差: 0.8765  (噪声降低 29.0%)
  溶解氧(DO)         滤波前标准差: 2.3456  →  滤波后标准差: 1.5432  (噪声降低 34.2%)
  pH                    滤波前标准差: 0.2345  →  滤波后标准差: 0.1543  (噪声降低 34.2%)
  盐度(Salinity)      滤波前标准差: 1.8765  →  滤波后标准差: 1.2345  (噪声降低 34.2%)
```

**理论分析**：

| 窗口大小 | 平滑程度 | 噪声抑制 | 细节保留 | 适用场景     |
| -------- | -------- | -------- | -------- | ------------ |
| 3 (k=1)  | 轻度     | 约20-30% | 优秀     | 短期波动分析 |
| 5 (k=2)  | 中度     | 约30-45% | 良好     | 日常监测     |
| 7 (k=3)  | 较强     | 约40-55% | 一般     | 日趋势分析   |
| 9 (k=4)  | 强       | 约50-65% | 较弱     | 周趋势分析   |
| 11 (k=5) | 最强     | 约55-70% | 较差     | 长期趋势分析 |

**结论**：

1. **窗口越大，噪声抑制越强**：窗口 N 增大 → 取平均的点数增多 → 随机噪声被更大程度地"平均掉" → 标准差下降更多。
2. **但窗口越大，细节损失也越大**：窗口 N=11 时，每一点的输出值包含了前后共50分钟（10×5分钟）的数据，短时间的真实变化（如增氧机开启导致的DO快速上升）会被平滑掉，可能掩盖重要的预警信号。
3. **推荐窗口为5或7**：在平滑度和细节保留之间取得较好平衡。对于水质监测场景，30-35分钟的时间窗口足以滤除传感器噪声，同时不会错过有意义的短期变化。

### 滤波前后标准差变化的数学解释

移动平均滤波器的频率响应函数为：

\[
H(f) = \frac{\sin(\pi f N)}{N \sin(\pi f)}
\]

这是一个**低通滤波器**——低频（长期趋势）通过，高频（噪声）被抑制。窗口越大，截止频率越低，对高频噪声的抑制越强。

标准差衡量的是数据的**总波动**（信号波动 + 噪声波动）。滤波后标准差降低的部分，就是被滤除的噪声成分。因此：

\[
\text{噪声降低比例} = \left(1 - \frac{\sigma_{滤波后}}{\sigma_{滤波前}}\right) \times 100\%
\]

## 附录：模块二程序流程图

```
用户选择 [2] 数据预处理
    │
    ├── [1] 检测与处理异常值
    │       │
    │       ├── 第一遍扫描：统计每条有效记录的异常参数个数
    │       │     └── 输出概览：总记录数/异常记录数/异常参数数/时间跨度
    │       │
    │       ├── 异常参数 ≥ 3 → 标记待删除
    │       └── 异常参数 < 3 → 均值逼近法填充异常参数
    │             │
    │             ├── 向前找第10个有效值
    │             ├── 向后找第10个有效值
    │             ├── 两方向都有 → 取均值
    │             ├── 仅一方向 → 取该方向值
    │             └── 两方向都无 → 取全局均值
    │
    ├── [2] 缺失值处理（均值逼近法）
    │       │
    │       ├── 遍历所有 invalid 记录
    │       ├── 对每个 NaN 参数调用均值逼近法
    │       └── 填充完毕后标记 record.valid = true
    │
    ├── [3] 移动平均滤波
    │       │
    │       ├── 用户选择窗口大小 (3/5/7/9/11)
    │       ├── 对水温/DO/pH/盐度分别滤波
    │       │     ├── 保存原始值
    │       │     ├── 计算原始标准差
    │       │     ├── 应用移动平均（含边界处理）

    │       │     └── 输出对比结果
    │       └── 显示分析讨论
    │
    ├── [4]/[5] 保存处理后数据
    │
    ├── [6] 查看预处理统计
    │
    └── [0] 返回主菜单
```
