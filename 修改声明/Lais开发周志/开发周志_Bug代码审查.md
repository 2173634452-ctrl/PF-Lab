## 二、发现的主要问题

### 函数签名不匹配导致权限系统失效

这是本次审查发现的最严重的问题，也是一个比较隐蔽的 Bug。

`ui.h` 中声明的两个函数是带 `UserRole role` 参数的：

```c
void show_main_menu(UserRole role);
void handle_menu_choice(int choice, WaterDataset **dataset, UserRole role);
```

但 `ui.c` 中对应的实现却是没有这个参数的：

```c
void show_main_menu(void) { ... }
void handle_menu_choice(int choice, WaterDataset **dataset) { ... }
```

而 `main.c` 里调用这两个函数时是按头文件签名传了 `role` 的。在 C 语言中，实参和形参不匹配属于未定义行为。实际后果就是：`auth.c` 里写得规规矩矩的 `has_permission()` 从来没有被调用过，guest 登录后看到的菜单和 admin 一模一样，数据修改、删除这些操作全都敞开着。

修复本身不复杂——给两个函数补上 `UserRole role` 参数，在 `show_main_menu` 里根据角色分别构造菜单项，在 `handle_menu_choice` 的入口处加一道 `has_permission` 检查，权限不对就直接拦下来。顺便还修了一个附带问题：`display_text_file` 这个 static 函数在主菜单处理函数中引用了但定义在后面，没有前向声明，编译会报 implicit declaration 的 warning，加上声明就干净了。

### 二进制随机读取功能缺失

任务书 1.3(2) 要求顺序读取和随机读取都支持。目前 `load_binary_data()` 是把整个文件一块读进来，顺序读没问题，但随机定位（比如根据记录号直接 `fseek` 跳转然后读单条）没有实现。

### 滤波多窗口自动对比未实现（已修复）

任务书 2.3(1) 要求"分别用窗口 3、5、7、9、11"对四个参数进行滤波。之前只能手动选一个窗口，不能一次性跑完五个窗口做横向对比。任务书 2.3(4) 要求的"确定最佳滤波窗口"也只能靠反复尝试。

已于同日修复：新增 `compare_filter_windows()` 函数，输入 `0` 即可自动对比全部窗口并推荐最佳选择。

### 存储性能对比只有数据没有分析

`compare_storage_performance()` 能跑出 CSV 和二进制两种格式的文件大小、读写时间，表格很漂亮，但任务书 1.3(5) 还要求讨论适用场景以及"为什么实际存储大小与理论原始数据大小有区别"。这部分讨论文字在 design 文档里有，但程序运行时不输出。

### 预测准确度分析比较薄弱

模型训练和评估的数值结果是有的（R²、RMSE），但任务书 4.1(4) 要求的"分析预测准确度并分析相关原因"在程序输出中只有几句泛泛的局限性描述，没有结合具体的 R² 和 RMSE 数值展开定量讨论。

## 四、收获

这次审查最大的体会是：**头文件和源文件的签名一致性不能光靠眼睛扫，编译器在 C 语言下对这种不匹配不一定报 error（取决于编译器），但运行时行为是无法预期的。** `show_main_menu` 和 `handle_menu_choice` 这个 Bug 之所以能藏到现在，很可能就是因为之前编译时没有开 `-Wall`，或者编译器对这种实参多于形参的调用只给了 warning 没有给 error。这也印证了 `-Wall` 作为强制编译选项的必要性。

另一个感受是权限这类横切关注点，如果只是在底层写好检查函数但不接入调用链，那跟没写差不多。正确的做法应该是在入口处就做拦截，而不是指望每个子函数自己去检查。

## 五、修复实施

审查完成后，针对其中两个明确属于代码层面的问题进行了修复。

### 移动平均滤波全窗口对比（模块二）

任务书 2.3(1) 要求"分别用窗口 3、5、7、9、11"做滤波，但之前只能一个一个手动选。这次做了三件事：

1. 把移动平均的核心算法从 `apply_moving_average` 里抽出来，写了一个独立的 `apply_ma_to_array()` 函数，接受任意 double 数组，算完结果不碰原数据。这样单个窗口滤波和全窗口对比可以共用同一段逻辑，不用维护两份代码。

2. 基于这个公共函数，写了 `compare_filter_windows()`。它做的事是：先把水温、DO、pH、盐度四个参数的当前值各存一份副本，然后用 3/5/7/9/11 五个窗口分别对每份副本做滤波、算降噪率，最后打印一张对比表。整个过程不修改内存中的数据，等用户看完对比表决定了用哪个窗口，才真正写进去。

3. 在 `interactive_moving_average` 的界面上加了一个输入 `0` 的入口，提示文字也更新了，让用户知道有这个选项。

### 死代码清理（模块五）

`display_report_menu()` 在 `ui.h` 里声明了、`ui.c` 里也写了实现，但实现只有一句"报告查看功能尚未实现"，而且整个项目里没有任何地方调用它——主菜单的报告查看走的是 `handle_menu_choice` 里的 case 5/6/7。这类残留代码留着只会让后来的人困惑，所以直接从声明到实现都删了。

### 额外整理

- 所有修改编译通过，`-Wall` 零警告
- 操作说明同步更新到 v1.3，新增了自动对比模式的操作步骤和截图式示例

## 七、修复后终审（模块二 & 模块五）

修复工作完成后，对模块二和模块五做了最后一轮审查，确认代码既符合任务书要求，也没有残留的语法或逻辑问题。

### 编译与死代码验证

先用 `gcc -std=c11 -Wall -Iinclude src/*.c -o seawater_analysis.exe -lm` 编译，零错误零警告，生成可执行文件 578KB。

然后全项目搜索了 `display_report_menu`，确认这个词已经从所有源文件和头文件中消失，只出现在修改声明和开发周志这些文档里（作为历史记录提及）。死代码清理是干净的。

### 模块二逐项核对

**异常值检测（2.1）**：`is_param_in_range()` 覆盖了全部 6 个参数，范围值与任务书的表完全一致。`count_outliers()` 对每个参数先做 `!isnan()` 判断再比较范围——NaN 不会误计为异常值，这个在之前的修复中已经改好了。处理逻辑是 ≥3 个异常删记录、<3 个用均值逼近法填，两遍扫描的流程没有问题。输出概览表包含了任务书要求的所有字段（总记录数、异常记录数、有效记录数、时间跨度、异常参数个数），统计信息也通过 `append_preprocess_overview()` 写入了 data_overview.txt。

**缺失值处理（2.2）**：均值逼近法 n=m=10，三级兜底（双方向→单方向→全局均值）实现正确。`fill_missing_values()` 遍历 `valid=false` 的记录，对其中每个 `isnan()` 字段独立填充，填充完把 `valid` 置回 true。边界情况处理到位——比如数据集开头或结尾附近找不到足够的参考值时，会降级使用能找到的值。

**移动平均滤波（2.3）**：滤波对象是水温、DO、pH、盐度四个参数，和任务书 2.3(1) 的要求一致。新增的 `compare_filter_windows()` 一次性跑完 3/5/7/9/11 五个窗口，输出横向对比表，标注最佳降噪窗口，最后让用户选择应用哪个——整个过程不修改内存数据，只在用户确认后才真正写入。边界处理用的是非对称窗口（开头和结尾有多少个数据点就算多少的平均）。公共函数 `apply_ma_to_array()` 同时服务于单窗口滤波和全窗口对比，没有冗余代码。

### 模块五逐项核对

**用户登录与权限（5.1）**：预设账户 admin/123456 和 guest/guest 与任务书完全一致。登录限 3 次尝试。`show_main_menu()` 根据角色动态显示不同菜单——admin 看到全部 10 项，guest 只看到 [5] 数据概览、[7] 分析报告、[9] 清屏、[0] 退出。`handle_menu_choice()` 在 switch 分发之前先过 `has_permission()` 这道门，guest 尝试进入未授权功能时直接被拦下并提示"权限不足"。头文件和源文件的函数签名已经对齐，不存在之前那种参数不匹配的问题。

**菜单交互（5.2）**：主菜单在 `main()` 里用 while 循环实现，四个模块的子菜单各自有 `while (sub_choice != 0)` 的循环。输入错误时 scanf 失败会被捕获，清缓冲区后提示重新输入。退出时调用 `confirm_action("退出系统")`，有确认环节。

**系统集成检查（5.3）**：多文件 .c/.h 分离、`#ifndef` 头文件保护、命名规范、注释这几项都到位。`ensure_data_loaded()` 在关键操作前做了数据是否加载的判断。逐个核对了 `auth.h↔auth.c`、`ui.h↔ui.c`、`preprocess.h↔preprocess.c` 的所有函数签名，全部匹配，没有一个漏掉的。

### 一处设计层面的说明

`preprocessed` 标志在预处理子菜单中，每执行一个子步骤（异常值/缺失值/滤波）就立即置为 true。严格来说单独跑一个步骤并不等于"完成全部预处理"，但任务书本就允许各步骤独立执行——你可以只做异常值检测不做滤波，这是合理的用法。而且模块三分析入口处有预处理状态提示和二次确认弹窗，不是静默跳过。所以这个设计没有问题，不需要修改。
