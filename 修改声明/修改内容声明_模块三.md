## 三、功能覆盖情况（对照任务书）

### 3.1 基本统计量 ✅

**任务要求**：
- ✅ 计算每个参数的均值、最大值、最小值、标准差
- ✅ 统计结果写入统计分析报告（CSV格式）
- ✅ 样本仅取有效记录（`valid == true`）

**实现要点**：
- 一次遍历提取6个参数的有效值数组，O(n) 时间复杂度
- 统计函数（mean/max/min/stddev）独立封装，可复用
- 控制台 + CSV 文件双输出

### 3.2 分段统计 ✅

**凌晨缺氧预警**：
- ✅ 根据时间序列起止时间和5分钟采集频率筛选数据段
- ✅ 筛选每天 03:00-05:00 的 DO 数据求均值
- ✅ DO 均值 < 4.0 → 亚缺氧预警 + 建议开增氧机
- ✅ DO 均值 < 3.0 → 严重缺氧预警 + 建议投颗粒氧并减投喂
- ✅ 预警写入 `reports/warning_report.csv`

**盐度突变预警**：
- ✅ 1小时变化率：基于真实时间戳（双指针滑动窗口，55-65分钟容差），变化 > 2 PSU → 预警
- ✅ 24小时累计降幅：日窗口 max−min > 5 PSU → 预警
- ✅ 预警写入 `reports/warning_report.csv`

### 3.3 相关性分析 ✅

**任务要求**：
- ✅ 实现皮尔逊相关系数计算函数
- ✅ 输出完整 6×6 相关系数矩阵
- ✅ 找出最强正相关和最强负相关
- ✅ 分析四组特定参数对：水温-DO、pH-DO、水温-气温、水温-盐度
- ✅ 矩阵及结论写入统计分析报告（CSV格式）

**实现要点**：
- 皮尔逊公式采用单遍累加：`r = (n·Σxy − Σx·Σy) / √[(n·Σx²−(Σx)²)·(n·Σy²−(Σy)²)]`
- 对角元强制为 1.0，方差为零返回 NAN
- 相关强度自动标注（极强/强/中等/弱/极弱）

## 六、BUG 修复记录

> 以下 BUG 在模块三初次实现后发现并修复，涉及跨文件改动。

### BUG-1：CSV 列数不匹配导致所有数据显示 0.0

| 项目 | 说明 |
|------|------|
| **严重程度** | 🔴 严重 — 数据读取全部失效 |
| **根因** | CSV 文件实际为 **6 列**（无时间戳列），但 `data_io.c` 中 `load_csv_data` 的解析器按 `field_count < 7` 过滤行，导致 **所有 23,203 条记录被跳过**，显示全为零值 |
| **修复** | `field_count < 7` → `< 6`；增加 `offset` 变量适配 6/7 列两种格式；对 6 列 CSV 自动按 5 分钟间隔生成时间戳 |
| **影响文件** | `src/data_io.c` 第 191-216 行 |

### BUG-2：时间戳自动生成溢出（非法日期）

| 项目 | 说明 |
|------|------|
| **严重程度** | 🟡 中等 — 后期记录的日期显示异常 |
| **根因** | 时间戳用硬编码字符串 `"2024-01-%02d"` 拼凑，`sprintf` 的日期索引按 `i/288` 直接递增。当记录数超过 31 天时产生 `2024-01-81`、`2024-01-99` 等非法日期 |
| **修复** | 改用 `mktime()` + `localtime()` + `strftime()` 标准日历函数正确计算日期；时间基准从 2024-01-01 改为任务书要求的 **2025-01-01 12:00** |
| **影响文件** | `src/data_io.c` 第 203-216 行 |

### BUG-3：盐度突变 1 小时检测使用固定索引偏移

| 项目 | 说明 |
|------|------|
| **严重程度** | 🟡 中等 — 删除记录后检测结果不准确 |
| **根因** | 1 小时检测使用 `records[i]` vs `records[i-12]`，假设 12 条 = 1 小时。执行单条删除、批量删除后，索引偏移不再对应真实时间差，12 条记录可能对应几个小时甚至更长时间 |
| **修复** | 新增 `timestamp_to_minutes()` 辅助函数，将时间戳解析为 epoch 分钟；**双指针滑动窗口法**：外层 `i` 扫描，内层 `prev` 追赶，当 `gap ∈ [55, 65]` 分钟时才进行比较 |
| **影响文件** | `src/analysis.c`：新增 `timestamp_to_minutes()`（第 83-98 行）、重写 `salinity_warning` 1 小时部分（第 342-385 行） |

### BUG-4：盐度突变 24 小时检测使用固定批次

| 项目 | 说明 |
|------|------|
| **严重程度** | 🟡 中等 — 删除记录后分组错位 |
| **根因** | 24 小时检测每 288 条记录为一批（`for block in 0..n/288`）。删除记录后，批次的 288 条边界不再与日历日对齐，造成跨天数据混在一起比较 |
| **修复** | 改用 `extract_date()` 按日历日期（YYYY-MM-DD）分组，与缺氧预警的分组策略一致。删除记录不影响日期分组精度 |
| **影响文件** | `src/analysis.c`：`salinity_warning` 24 小时部分（第 391-435 行） |

### BUG-5：数据分析前缺少预处理提醒

| 项目 | 说明 |
|------|------|
| **严重程度** | 🟢 体验 — 用户可能用脏数据做分析 |
| **根因** | 分析模块未检查数据是否已完成预处理（异常值检测 + 缺失值填充 + 移动平均滤波），用户可能在未清洗数据的情况下直接进入模块三分析，导致统计结果被异常值/缺失值干扰 |
| **修复** | `WaterDataset` 新增 `preprocessed` 标志位；`handle_analysis_submenu` 在进入分析前检测标志位，弹出 Y/N 确认对话框提醒用户；预处理完成后自动置 `true`；数据修改/删除后自动重置为 `false` |
| **影响文件** | `include/common.h`（新增字段）、`src/ui.c`（第 379-526 行）、`src/data_io.c`（第 147/756/817/901 行） |

### BUG-6：修改/删除后预处理标记未失效

| 项目 | 说明 |
|------|------|
| **严重程度** | 🟢 体验 — 标记与实际数据状态不一致 |
| **根因** | `modify_single_record`、`delete_single_record`、`batch_delete_records` 会改变数据内容，但未重置 `preprocessed` 标志，导致系统仍显示"预处理已完成" |
| **修复** | 三个修改/删除函数执行后均将 `dataset->preprocessed = false`，确保标记反映真实数据状态 |
| **影响文件** | `src/data_io.c`（第 756/817/901 行） |

### BUG 修复总结

| BUG | 模块 | 根因 | 修复策略 |
|-----|------|------|---------|
| BUG-1 | 数据读取 | CSV 列数硬编码 7 → 改为 6 | 灵活列数 + offset 适配 |
| BUG-2 | 数据读取 | `sprintf` 拼凑日期 | `mktime` + `strftime` |
| BUG-3 | 统计分析 | `records[i-12]` 固定索引 | 双指针 + `timestamp_to_minutes` |
| BUG-4 | 统计分析 | 288 条固定批次 | `extract_date` 日历分组 |
| BUG-5 | 系统集成 | 无预处理检查 | `preprocessed` 标志 + Y/N 确认 |
| BUG-6 | 数据操作 | 修改后标记未更新 | 操作后重置标志位 |

## 八、与其他模块的关系

```
模块一（数据加载）
    ↓ 传入 WaterDataset*
模块二（数据预处理）
    ↓ 传出清洗后的 WaterDataset*
模块三（统计分析）← 本次实现
    ↓ 产出统计报告 + 预警报告
模块五（系统集成）
```

- **依赖模块一/二**：需要先加载数据并（可选）执行预处理
- **数据不修改**：所有分析均为只读操作，不改变内存中的 `WaterDataset`
- **模块四（预测模型）**：与模块三同为数据消费层，互不依赖，可独立执行
